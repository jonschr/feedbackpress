# FeedbackPress interface

Operate mode: a compact, quiet review tool above an existing client website. Shadow DOM isolates it from the host theme. Widget button styles use fp-primary/fp-quiet/fp-icon-button classes and explicit local colors, with no WordPress button classes or theme token dependency. Use the host WordPress administration conventions for configuration.

Sidebar: a white, square-edged 400px drawer flush to the top, bottom, and selected left/right edge of the viewport (right by default), filling narrow screens. Fixed tools above a separately scrolling issue list; 16px semibold Issues heading with a quiet 12px count. Bundled Inter carries the whole interface, with system sans as a loading/error fallback. Flat rows show a numeric issue number with all five status icons aligned on the same line, followed by a two-line comment preview. Highlight the current icon instead of writing the status name. The default is All issues listed, Created: oldest first. A combined page-view menu offers All issues by page, All issues listed and Current page; status filtering sits beside it and the six-order native menu appears as a sort icon in the header. No product branding, reviewer identity, or written close control appears. The selected row uses its status tint, with a light gray fallback. Status icons have accessible labels and tooltips: amber To do, blue Doing, purple Review, green Done. Element pins remain small. No full-screen blocking dialog. Escape exits selection or closes the panel; page-level feedback provides a keyboard-accessible alternative to pointer selection.

Tokens: ink #20242b; secondary #626a76; action #191c21; surface #ffffff; soft surface #f5f6f8; divider #e1e4e8; field border #838c99; focus #343b45. Body and issue titles are 14px/20–21px; controls 13px/20px; authors 12px; list authors, dates, and paths 11px. Fields share a 6px radius, padding, border, and 2px inset focus indicator. Touch inputs use 16px to avoid mobile auto-zoom. Reduced-motion users get no entry animation or smooth locating scroll. Focus indicators, form labels, live notices, busy submit states, empty lists, missing targets, unavailable files, and status conflicts are explicit.

New feedback uses a 340px maximum floating composer tethered to the selected pin, repositioned within viewport edges and above the mobile keyboard. It contains an outlined comment field with an inset paperclip action, an icon-only close control, and a submit button. Selected files appear only after attachment; the multi-file picker supports additive selection and removal. Screenshots are automatic. The submit tooltip carries the keyboard shortcut; there is no heading, cancel text, screenshot checkbox, privacy helper, or persistent shortcut hint. Successful submission closes it without opening the issue sidebar and returns to pin placement. Closing a draft with X also returns to placement; Escape exits this mode, and reloading never restores it. Separate Leave feedback / View issues launchers distinguish creation from browsing while the drawer is closed. Both floating buttons hide throughout issue browsing; a plus action in the drawer header starts new feedback. X dismisses the drawer; X on a mobile conversation returns to the list, and V remains the list toggle. A one-time name prompt appears before interaction for guests; logged-in WordPress reviewers skip it. No issue, reply, or status form repeats the name field. Command+Enter and Ctrl+Enter submit the current form.

Pins display persisted issue numbers, never positions in a filtered or sorted list. The same reference appears in issue rows and details for conversations about specific feedback.

Opening an issue via a pin, row, or fragment link navigates to its page when needed and scrolls to the saved vertical point within the element, rather than the element center. Nested containers are revealed first. Fixed or unavailable elements do not cause artificial page jumps. Refreshing after replies, uploads, and statuses preserves scroll position.

Selected issue details use a separate 400px pin-anchored popup, at most 620px tall. Compact single-line header: issue number, all five status icons, previous/next arrows, and X. Highlight the current icon without a separate status badge above the scrollable conversation. Replies use a two-row field with an attachment icon; each comment has uploads in a left-aligned thumbnail strip and automatic screenshots in a separate right-aligned strip. Sidebar and popup are side by side at 900px and above, and switch views below that width. Closing only the list leaves the popup open. Cross-page navigation retains sort/filter/list position.

Status icons: clipboard To do, play Doing, eye Review, check Done; explicit local status colors. Always show all five icons, with aria-pressed and a colored border/background identifying the current status. Clicking the current status is a no-op except when resolving a conflict. Tooltips describe the destination or current state and hotkey. Status shortcuts are 1/2/3/4/5 respectively. The last issue deliberately used by mouse movement, selection or keyboard navigation owns those shortcuts; a stationary mouse, scrolling or a redraw cannot override keyboard navigation. Hovering a row or passive pin does not open it. One keypress changes one issue, with input/contenteditable, modifiers, repeat, composition, modal, placement and busy-state guards.

Attachment previews: 64px tiles in a horizontally scrolling strip, image thumbnails or labeled PDF document tiles. Clicking opens a native modal dialog lightbox up to 1600px wide, within 16px viewport edges, with filename, Download, X, and an image or native PDF frame. Sidebar thumbnails are separate native buttons outside the issue-open button; they preview directly without changing selection, URL or list scroll. Each sidebar thumbnail has a quiet download icon; each thread attachment/screenshot has a labeled Download action below it. Use the existing authenticated memory-only blob cache for downloads, showing busy/retryable errors on that control without blocking other interaction. The lightbox resolves attribution from its source issue even when another issue is selected, and clears when refresh removes that issue/file. Modal focus/Escape handling must not close the underlying issue or trigger status shortcuts. Restore focus to the thumbnail. Preview requests use authenticated blob URLs, reused in a short-lived in-memory cache across issues (30 seconds, at most eight ready entries/20 MiB), with safe object-URL release and full revocation on access denial or page exit. Command+Enter and Ctrl+Enter are handled during document capture using the focused widget form from the composed event path.

Media belongs to comments: original comment uses the issue UUID, replies use reply-event UUIDs. Place uploaded files below the comment text on the left, with automatic screenshots top-aligned on the right beside the text; both use the same preview/download controls. Queue reply files until submission, preserve them across status changes, and offer transfer retry without duplicating a posted comment. Legacy unassociated files remain under the original comment.

Keyboard routing: handle Escape, Up/Down issue navigation, status digits, and modified Enter at window capture, with composed-path input checks. Up/Down follow the active filtered/sorted list and its pagination, preserving query-bearing page URLs and saved list position; from an unselected list Down starts first and Up starts last. Navigation stops at the list ends. Escape dismisses all active feedback UI in one step (a lightbox closes first) and clears the shortcut target. Dismissal invalidates pending issue reads and UI callbacks from submitted writes, so a late response cannot reopen the interface or resume pin placement. Submitted data still finishes saving.

Comment identity: 12px semibold author names, with dates in separate 11px time elements. Keep each reply’s author distinct from its timestamp. Conversation area grows to 380px where the viewport permits; the popup is wider with smaller thumbnails. Attachment lightboxes show the associated comment’s author and never guess an author for a comment that has not synced yet.

Status filtering uses an accessible checkbox disclosure, allowing any combination of all five statuses, with To do + Information needed + Review as the new-session default. Retain checkbox focus and keep the menu open while selections update. Outside clicks close it; Escape closes the filter first and restores its trigger. List rows use 1px status-colored leading edges; issue popups have no leading border; Done rows/popups, their selected state, action icons, badges, and thumbnails are gray. Full attachment previews retain original colors.

Issue search: a single compact outlined search field above the sort/status row, labeled Search issues and replies. Debounce input by 200ms while preserving focus and caret across result renders; invalidate older requests immediately. Search combines with selected statuses and current-page pins, persists with the tab’s view, and retains the selected issue separately when it falls outside the matching list. Created, Last edited and Completed each offer oldest/newest first; missing completion dates sort last in both directions. Page paths stay visible in ungrouped sorts.

General controls use black, white, and neutral grays, including notices, focus, input borders/carets, selection, scrollbars, shadows, element highlights, and draft tethers. Reserve color for status indicators and warnings. A shared fixed bottom toolbar keeps launchers anchored to the bottom edge independently of notice height; below 900px, notices occupy a full row directly above right-aligned launchers. Hide launchers while browsing issues, and keep notices to the left of the desktop drawer. Toolbar gaps pass pointer events through to the page; composer/popup positioning reserves space above the toolbar, including when its height changes.

Tooltips: shared immediate hover/focus hints replace native control title tooltips. Use a near-black rounded surface, white action label, subtle arrow and shadow, and compact outlined shortcut key badge; unselected issue actions explain which issue shortcuts affect. No entrance delay or animation. Top-layer popovers escape scrolling panel bounds; lightbox hints live inside the dialog to remain hoverable above its modal surface. Clamp to the viewport, flip below controls near the top edge, keep visible while hovered, and clear descriptions on blur, click, scrolling, removal, disabling, and interface dismissal. Retain iframe titles for PDF accessibility.

Status hover states follow their semantic palette: warm amber To do, blue Doing, purple Review, and neutral gray Done. Unselected rows use a lighter status tint than selected rows; hovering a selected row retains its selected tint. Status action icons use the destination's foreground/background on hover, and filter option hovers follow their status tint. Completed issues retain gray overrides for their rows and actions.

Screenshot location marker: stamp an amber To do dot directly onto each new element-feedback capture at its original viewport coordinates, before JPEG encoding. Use a 24px filled circle, 2px white outline, 6px white center, and a subtle shadow. Freeze the point before asynchronous rendering and reset the canvas transform to viewport-to-image scaling, so scrolling and high-DPI output do not offset it. Keep review UI excluded; page-level feedback has no location marker. Existing captures stay unchanged.

Passive pins: show matching current-page pins independently of list visibility, including during placement and drafting. Keep the selected status/search filters (To do + Information needed + Review initially); an empty selection shows none. Existing pins remain clickable while placing new feedback. On creation acknowledgment, immediately cache and draw the matching numbered issue pin and hide its temporary draft dot while media transfers finish. A failed list refresh must not erase that confirmed pin. Escape exits active UI/placement while passive pins remain, including when an earlier read or submitted save finishes afterward.

Launcher shortcuts: C starts pin placement through the Leave feedback action; pressing C again outside editable controls exits placement or cancels the current draft while preserving an already-open issue list. Escape still closes the whole review interface. Inside inputs or editors, C remains normal text input. V invokes the View issues action, including mobile list/popup switching. Show C/V in launcher tooltip key badges and aria-keyshortcuts. Single-key shortcuts ignore native inputs, textareas/selects, editable ancestors (including open Shadow DOM), custom textbox/searchbox/combobox/spinbutton/slider/listbox/grid/tree controls, document designMode, modifiers, repeats, and composition. Opening or closing the sidebar clears obsolete placement instructions.

Status-change stability: retain the current list’s membership/order/count after a local status change, updating card data and styling in place. Preserve this snapshot through selecting/navigating issues, replies, and closing/reopening the sidebar. Keep out-of-filter edited cards in their original positions until a sort/filter change or browser reload; passive pins continue respecting filters. New matching issues append without shifting retained cards.
