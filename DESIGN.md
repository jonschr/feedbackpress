# FeedbackPress interface

Operate mode: a compact, quiet review tool above an existing client website. Shadow DOM isolates it from the host theme. Widget button styles use fp-primary/fp-quiet/fp-icon-button classes and explicit local colors, with no WordPress button classes or theme token dependency. Use the host WordPress administration conventions for configuration.

Sidebar: white surface, near-black actions, system typography, compact 15px Issues heading; 300px maximum desktop width, mobile viewport inset, independently scrolling. Flat rows show a permanent issue number with all four status icons aligned on the same line, followed by a two-line comment preview. Highlight the current icon instead of writing the status name. Issue-number ordering across all pages is the default; page grouping is available. All pages are included. No product branding, reviewer identity, or written close control appears. The selected row uses its status tint, with a light gray fallback. Status icons have accessible labels and tooltips: amber To do, blue Doing, purple Review, green Done. Element pins remain small. No full-screen blocking dialog. Escape exits selection or closes the panel; page-level feedback provides a keyboard-accessible alternative to pointer selection.

Tokens: ink #202020; secondary #5c5c5c; action #171717; surface #ffffff; divider #dedede; focus #444444. Reduced-motion users get no entry animation or smooth locating scroll. Focus indicators, form labels, live notices, busy submit states, empty lists, missing targets, unavailable files, and status conflicts are explicit.

New feedback uses a 320px maximum floating composer tethered to the selected pin, repositioned within viewport edges and above the mobile keyboard. It contains an outlined comment field with an inset paperclip action, an icon-only close control, and a submit button. Selected files appear only after attachment; the multi-file picker supports additive selection and removal. Screenshots are automatic. The submit tooltip carries the keyboard shortcut; there is no heading, cancel text, screenshot checkbox, privacy helper, or persistent shortcut hint. Successful submission closes it without opening the issue sidebar and returns to pin placement. Closing a draft with X also returns to placement; Escape exits this mode, and reloading never restores it. Separate Leave feedback / View issues launchers distinguish creation from browsing. A one-time name prompt appears before interaction for guests; logged-in WordPress reviewers skip it. No issue, reply, or status form repeats the name field. Command+Enter and Ctrl+Enter submit the current form.

Pins display persisted issue numbers, never positions in a filtered or sorted list. The same reference appears in issue rows and details for conversations about specific feedback.

Opening an issue via a pin, row, or fragment link navigates to its page when needed and scrolls to the saved vertical point within the element, rather than the element center. Nested containers are revealed first. Fixed or unavailable elements do not cause artificial page jumps. Refreshing after replies, uploads, and statuses preserves scroll position.

Selected issue details use a separate 384px pin-anchored popup, at most 620px tall. Compact single-line header: issue number, all four status icons, previous/next arrows, and X. Highlight the current icon without a separate status badge above the scrollable conversation. Replies use a two-row field with an attachment icon; each comment has uploads in a left-aligned thumbnail strip and automatic screenshots in a separate right-aligned strip. Sidebar and popup are side by side on desktop and switch views on narrow screens. Closing only the list leaves the popup open. Cross-page navigation retains sort/filter/list position.

Status icons: clipboard To do, play Doing, eye Review, check Done; explicit local status colors. Always show all four icons, with aria-pressed and a colored border/background identifying the current status. Clicking the current status is a no-op except when resolving a conflict. Tooltips describe the destination or current state and hotkey. Selected-issue shortcuts are 1/2/3/4 respectively, with input/contenteditable, modifiers, repeat, composition, and busy-state guards.

Attachment previews: 64px tiles in a horizontally scrolling strip, image thumbnails or labeled PDF document tiles. Clicking opens a native modal dialog lightbox with filename, Download, X, and an image or native PDF frame. Modal focus/Escape handling must not close the underlying issue or trigger status shortcuts. Restore focus to the thumbnail. Preview requests use authenticated blob URLs, cached only for the current issue and revoked on exit. Command+Enter and Ctrl+Enter are handled during document capture using the focused widget form from the composed event path.

Media belongs to comments: original comment uses the issue UUID, replies use reply-event UUIDs. Place uploaded files below the comment text on the left, with automatic screenshots top-aligned on the right beside the text; both use the same preview/download controls. Queue reply files until submission, preserve them across status changes, and offer transfer retry without duplicating a posted comment. Legacy unassociated files remain under the original comment.

Keyboard routing: handle Escape, status digits, and modified Enter at window capture, with composed-path input checks. Escape dismisses all active feedback UI in one step (a lightbox closes first). Dismissal invalidates pending issue reads and UI callbacks from submitted writes, so a late response cannot reopen the interface or resume pin placement. Submitted data still finishes saving.

Comment identity: 12px semibold author names, with dates in separate 10px time elements. Keep each reply’s author distinct from its timestamp. Conversation area grows to 360px where the viewport permits; the popup is wider with smaller thumbnails. Attachment lightboxes show the associated comment’s author and never guess an author for a comment that has not synced yet.

Status filtering uses an accessible checkbox disclosure, allowing any combination of all four statuses, with To do + Review as the new-session default. Retain checkbox focus and keep the menu open while selections update. Outside clicks close it; Escape closes the filter first and restores its trigger. List rows and issue popups use thin status-colored leading edges; Done rows/popups, their selected state, action icons, badges, and thumbnails are gray. Full attachment previews retain original colors.

Issue search: a single compact outlined search field above the sort/status row, labeled Search issues and replies. Debounce input by 200ms while preserving focus and caret across result renders; invalidate older requests immediately. Search combines with selected statuses and current-page pins, persists with the tab’s view, and retains the selected issue separately when it falls outside the matching list. Date sort choices are Completed: newest and Last edited: newest; page paths stay visible in ungrouped sorts.

General controls use black, white, and neutral grays, including notices, focus, input borders/carets, selection, scrollbars, shadows, element highlights, and draft tethers. Reserve color for status indicators and warnings. A shared fixed bottom toolbar vertically centers notices and launcher buttons on desktop; below 760px, notices occupy a full row directly above right-aligned launchers. Toolbar gaps pass pointer events through to the page; composer/popup positioning reserves space above the toolbar, including when its height changes.

Tooltips: shared immediate hover/focus hints replace native control title tooltips. Use a near-black rounded surface, white action label, subtle arrow and shadow, and compact outlined shortcut key badge; unselected issue actions explain which issue shortcuts affect. No entrance delay or animation. Top-layer popovers escape scrolling panel bounds; lightbox hints live inside the dialog to remain hoverable above its modal surface. Clamp to the viewport, flip below controls near the top edge, keep visible while hovered, and clear descriptions on blur, click, scrolling, removal, disabling, and interface dismissal. Retain iframe titles for PDF accessibility.

Status hover states follow their semantic palette: warm amber To do, blue Doing, purple Review, and neutral gray Done. Unselected rows use a lighter status tint than selected rows; hovering a selected row retains its selected tint. Status action icons use the destination's foreground/background on hover, and filter option hovers follow their status tint. Completed issues retain gray overrides for their rows and actions.

Screenshot location marker: stamp an amber To do dot directly onto each new element-feedback capture at its original viewport coordinates, before JPEG encoding. Use a 24px filled circle, 2px white outline, 6px white center, and a subtle shadow. Freeze the point before asynchronous rendering and reset the canvas transform to viewport-to-image scaling, so scrolling and high-DPI output do not offset it. Keep review UI excluded; page-level feedback has no location marker. Existing captures stay unchanged.

Passive pins: show matching current-page pins independently of list visibility, including during placement and drafting. Keep the selected status/search filters (To do + Review initially); an empty selection shows none. Existing pins remain clickable while placing new feedback. On creation acknowledgment, immediately cache and draw the matching numbered issue pin and hide its temporary draft dot while media transfers finish. A failed list refresh must not erase that confirmed pin. Escape exits active UI/placement while passive pins remain, including when an earlier read or submitted save finishes afterward.

Launcher shortcuts: C starts pin placement through the Leave feedback action; if a draft already exists, focus its comment without discarding it. V invokes the View issues action, including mobile list/popup switching. Show C/V in launcher tooltip key badges and aria-keyshortcuts. Single-key shortcuts ignore native inputs, textareas/selects, editable ancestors (including open Shadow DOM), custom textbox/searchbox/combobox/spinbutton/slider/listbox/grid/tree controls, document designMode, modifiers, repeats, and composition. Opening or closing the sidebar clears obsolete placement instructions.
