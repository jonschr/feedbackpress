# FeedbackPress interface

Operate mode: a compact, quiet review tool above an existing client website. Shadow DOM isolates it from the host theme. Widget button styles use fp-primary/fp-quiet/fp-icon-button classes and explicit local colors, with no WordPress button classes or theme token dependency. Use the host WordPress administration conventions for configuration.

Sidebar: retain the 400px white drawer, fixed controls and independently scrolling full-bleed list. The header shows authorized project-wide open and closed totals. Search, page view and status filter share one control type size, weight, border and height. Every issue body stays white, including hover and selection. A 48px semantic rail holds its stable plain numeric reference (without #) at the top and an icon plus numeric reply count at the bottom (no visible reply word; accessible labels retain it). Color belongs to the rail, pins and status filter indicators. Titles lead, with quieter author/private labels below, followed by a separate user-upload strip. Status actions align with the bottom of the attachments/author and reveal on row hover or focus-within without shifting geometry; on touch they stay visible. Hover/keyboard focus sweep semantic ink into the rail from left to right; selection retains a filled rail, with a deeper sweep on active hover. The white body has no hover or active outline. Use a 140ms rail fill and a <=96ms staggered 4px control rise only when motion is allowed. All five status glyphs use the same rounded geometry without active-state dots. Sidebar actions use semantic ink/soft fills matching the rail; card controls share the same semantic ink/fill treatment. Page groups use a light neutral surface, dark single-line title and muted URL; links underline only on hover. Preserve page grouping, all six orders, current-page query scope, full-thread search, keyboard shortcuts, drag/drop and exact list position.

Tokens: three type sizes (12px metadata/compact toolbar, 14px content/other desktop controls, 16px headings/touch editing), three weight roles (400 normal, 500 medium, 600 strong). Search and both filters always use the same control token. Neutral text has two roles only: ink #20242b and muted #626a76; status rail text retains its semantic contrast color. All ordinary borders use --fp-line #cbd0d8, with --fp-field as an alias. Strong keyboard focus and destructive states remain intentional semantic exceptions. White/soft/active surfaces share the neutral palette; semantic ink/fill pairs are root tokens, reused by rails, pins, filters and warnings. Use one bundled Inter variable face, without new fonts or dependencies. Preserve accessible contrast, focus, real pressed states, forced-color outlines and reduced-motion behavior. WordPress admin retains its native system styles separately.

New feedback uses a 340px maximum floating composer tethered to the selected pin, repositioned within viewport edges and above the mobile keyboard. It contains an outlined comment field with an inset paperclip action, an icon-only close control, and a submit button. Selected files appear only after attachment; the multi-file picker supports additive selection and removal. Screenshots are automatic. The submit tooltip carries the keyboard shortcut; there is no heading, cancel text, screenshot checkbox, privacy helper, or persistent shortcut hint. Successful submission closes it without opening the issue sidebar and returns to pin placement. Closing a draft with X also returns to placement; Escape exits this mode, and reloading never restores it. Equal-width white launchers stack at the bottom-right: View issues with a list icon above Leave feedback with a plus icon, with 8px between and 44px minimum targets. Use the same dark text, neutral hover/pressed fills and soft offset shadow for both. Guest introduction and mobile progress cards stay above the taller stack. Launcher tooltips sit beside their button (or above the whole stack when space is too narrow), so they never cover the other action. These distinguish creation from browsing while the drawer is closed. Both floating buttons hide throughout issue browsing; a plus action in the drawer header starts new feedback. X dismisses the drawer; X on a mobile conversation returns to the list, and V remains the list toggle. A one-time name prompt appears before interaction for guests; logged-in WordPress reviewers skip it. No issue, reply, or status form repeats the name field. Command+Enter and Ctrl+Enter submit the current form.

Pins display persisted issue numbers, never positions in a filtered or sorted list. The same reference appears in issue rows and details for conversations about specific feedback.

Opening an issue via a pin, row, or fragment link navigates to its page when needed and scrolls to the saved vertical point within the element, rather than the element center. Nested containers are revealed first. Fixed or unavailable elements do not cause artificial page jumps. Refreshing after replies, uploads, and statuses preserves scroll position.

Compact header: all five status icons at the left, then previous/next navigation and the owner’s issue-level three-dot menu immediately before X on the right. The menu uses a subtle neutral button surface and clearly drawn dots. The issue number sits beside the author/date below the original title and description, rather than in the action bar. Highlight the current icon without a separate status badge above the scrollable conversation. Use separators only between thread items, with no trailing rule above the reply field; each comment has uploads in a left-aligned thumbnail strip and automatic screenshots in a separate right-aligned strip. Sidebar and popup are side by side at 900px and above, and switch views below that width. Closing only the list leaves the popup open. Cross-page navigation retains sort/filter/list position.
