# Client review link

Current source uses one reusable link per HTTPS site connection. In **Settings → FeedbackPress → Review access**, **Every visitor / Logged-in administrators / Nobody (disabled)** controls who can use FeedbackPress without a link. New installations default to Logged-in administrators; explicitly saved access choices remain in effect. A valid client link enables shared feedback through the administrator-only gate; Nobody disables all review access.

In the frontend overlay, open **View issues** and click the **Invite reviewers** share icon in the sidebar footer. A compact bar opens directly above it. Type an email address; existing site users are suggested by name/login email. Choose **Send invitation** (the send icon). The gateway resolves selected user details from WordPress; no retyping or account creation is needed. The email briefly explains comments, text suggestions and replies, with a preferred login link and a guest magic link. Both open the issues sidebar. Clicking either accepts the invitation and adds its recipient to mentions; it does not identify the visitor as that person or subscribe them to unrelated tickets. Ticket notifications still depend on shared participation.

Choose **Copy magic link** (the link icon beside the email field) to write your own message. Copying remains independent of recipient selection/email validation, sends no mail, and opens the sidebar through the reusable site grant. Any connected site's WordPress administrator can share; subscription ownership is not required. Email delivery must be configured on the central service. Failed sends preserve the selection/address and reuse the same operation ID and issue time, keeping provider retries identical.

Anyone holding the link can use shared issues, replies, attachments and status changes. With a valid review session, opening the sidebar, reading tickets and viewing attachments requires no account, login, name or email. Ask for a name and email when the visitor submits a reply or starts a new ticket/text suggestion; other changes still require identification. Cancelling that prompt preserves the reply text and queued files. Access without a review link retains its existing identity prompt. It grants no WordPress login, verified email, administration or private-note identity. Private notes still require project access and a logged-in WordPress user with the matching server-resolved email.

The URL fragment is exchanged for a Secure/HttpOnly/SameSite=Lax site cookie and removed from the browser address/history. Original query strings and issue fragments are preserved. Browser sessions last up to 30 days; reopening a reusable link starts another session. **End review session** ends only that browser's session. Manually copied reusable grants have no expiry; emailed invitation entry links expire after seven days. Links are scoped to the current HTTPS site/project/connection credential; replacing/disconnecting it invalidates access. No per-recipient access account or invitation-grant table is added. Accepted invitation state lives on existing service people records; older local invitation metadata remains unused.

The central API derives a purpose-separated HMAC from the authenticated connection; the returned link cannot act as a service/project API credential. WordPress validates the same signature against its current server-side connection, without an additional network call for each pin/list permission check. Normal service requests still enforce site binding, current credentials, entitlement and project isolation. Gated cached HTML contains only the public bootstrap; reviewer configuration is fetched through the existing no-store session route. Hosting passwords/firewalls remain outer access controls.

## Testing and installation

See the canonical service PILOT-OPERATIONS.md and CENTRAL-SERVICE-PLAN.md for the installed releases, validation receipts and rollback. The service and plugin must be updated together; the earlier invitation-management version has a different endpoint contract. Email invitations use the configured central Resend transport, with capture-only mode for tests; copying a link sends no email.

## Share an individual issue

WordPress administrators can choose **Copy magic link** from a shared issue's three-dot menu, in its card or sidebar row. This combines the existing site review grant with the issue's full relative page/query and a ticket return fragment. It opens that ticket directly; the grant still permits the project's shared review access, not only that ticket. Copying creates no issue or email. Private issues and private notes do not offer this action. Other administrators can copy links for shared tickets they did not author without gaining edit/delete controls. If clipboard access fails, a selected readonly URL is available for manual copying.

Identity prompts put **Log in to this site** first, returning to the current page/ticket, followed by the name/email guest form. The login URL comes from WordPress and honors its login filters. A WordPress login takes precedence over guest attribution and a concurrent review-link session; the link does not log anyone out, switch users or replace their private-note identity.


Agents should retrieve a shared ticket’s direct magic link with the **feedbackpress/ticket-link** MCP/Abilities tool, **wp --user=<administrator> feedbackpress link <issue-uuid>**, or **GET feedbackpress/v1/issues/<uuid>/review-link**. Use that URL when referencing the ticket in chat. These helpers require a site administrator, preserve the ticket page/query and reject private tickets; they never grant private-note access.

## Notification email links

The pending service update gives owner/participant summaries and mention emails recipient-specific ticket links. The email entry link expires after seven days. Opening it checks the current shared ticket, enabled account and original active site connection, then uses the plugin's existing magic-review session. It preserves the ticket's current path/query; reconnecting/removing the site, deleting the ticket or making it private prevents redemption. No plugin update is needed for this service feature on installations already supporting magic links.

Forwarding the email also forwards access to the project's shared feedback, as with a manually copied review link. It does not authenticate the visitor as the recipient or grant private-note access. Existing WordPress login takes precedence, and guests identify themselves when writing. The resulting review session retains its existing lifetime; the seven-day limit applies to opening the emailed entry link. The signed proof stays in the URL fragment and is removed before exchange, outside HTTP/referrer logs. Already delivered emails are unchanged.
