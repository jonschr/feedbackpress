# Client review links

In **Settings → FeedbackPress → Review access**, choose who may use FeedbackPress without a link: **Every visitor**, **Logged-in administrators**, or **Nobody (disabled)**. Administrator-only mode hides review tools from ordinary visitors; an authorized client link enables shared review without a WordPress login. Nobody also blocks link access.

**Who can create review links?** is separate: **Administrators only** by default, or **Everyone with review access**. Everyone permits existing reviewers to invite others; it does not let an uninvited visitor create access on a gated site. Administrators manage and revoke all links.

Open **Client review links**, enter a label, choose 1, 7 or 30 days, and **Create review link**. Copy the new URL before leaving the page, then send it to the client using your normal communication channel. The saved list contains labels and expiry dates, with **Revoke**, but cannot recover the original URL. Eligible reviewers can also create a seven-day link to the current page from **Sidebar settings**. Email delivery remains deferred; this feature does not send email automatically.

Anyone holding the link can review shared issues, reply, upload attachments and change statuses until expiry or revocation. The usual name/email prompt provides comment attribution. The link does not log them into WordPress, verify their email, grant administration or authorize private notes. Entering a private-note owner's email as a guest does not grant private access. Private notes still require the matching server-resolved logged-in WordPress email plus project access.

The browser exchanges a URL fragment for a Secure, HttpOnly, SameSite=Lax site cookie, then removes the credential from its address/history. Existing query parameters and issue/section fragments are retained. The client can use **End link access** in Sidebar settings. Revocation and expiry are checked on every gateway request; previously read material is not remotely erased from a person's device. The existing active refresh clears denied shared data on its next request.

Links are bound to this HTTPS site, project, WordPress salts and project connection credential. They do not unlock another connected environment. A site copy, changed project, reconnected credential or changed salts requires a new link. Ordinary disconnected/disabled/expired central account access remains denied by the service. Review-link hashes are plugin-owned WordPress settings, not shared feedback or a new service identity/account system. Existing feedback is never moved or deleted by link operations.

Gated pages include only a small public bootstrap. Visitors without a link/session hint make no additional permission request. Authorized configuration is obtained from a private, non-cacheable REST response after the current access check; it is not embedded in gated page HTML. The same public cached HTML therefore works for invited clients without exposing feedback to ordinary visitors. Private notes never enter persistent browser snapshots. Hosting/CDN rules must allow the site's REST API and cookies; the plugin cannot bypass a hosting password or firewall.
